# ТЗ: аннотирование контента

Статус: реализовано. Действующий контракт описан в `docs/03-api-contract.md` и
`openapi.yaml`; этот файл сохраняет проектные решения и ограничения.

## 1. Назначение и принятое исключение

Добавить отдельный метод, который формирует краткую аннотацию контента на русском
языке в 2–3 предложениях. Входом служит ровно один из трёх вариантов:

- `url`: сервис скачивает публичную страницу и извлекает основной текст;
- `html`: сервис очищает переданный HTML и извлекает основной текст;
- `text`: сервис передаёт полученный текст модели без очистки или перефразирования.

Методу `annotate` разрешён выход к внешнему ИИ-провайдеру. Извлечённый или прямо
переданный текст уходит выбранному провайдеру для аннотирования. Это явно
согласованное исключение из требований FR-001 и NFR-006 к локальному переводу.
`/v1/translate` остаётся локальным и не меняет контракт. В первой версии у
`annotate` нет локального provider, поэтому без настроенного внешнего provider
метод недоступен.

Исключение закреплено в `docs/01-product-requirements.md`; контракт отражён в
`docs/03-api-contract.md`, `openapi.yaml` и тестах.

## 2. Публичный API

`POST /v1/annotate`, `Content-Type: application/json`.

Тело запроса — JSON-объект с ровно одним непустым полем из `url`, `html`, `text`.
Передача двух или трёх входов, либо ни одного, возвращает `400 invalid_request`.
Дополнительные поля верхнего уровня запрещены, кроме описанных ниже.

Примеры:

```json
{"url":"https://example.org/article"}
```

```json
{"html":"<html><body><main><p>Article content...</p></main></body></html>"}
```

```json
{"text":"Article content...","annotator":"iishko","annotator_params":{}}
```

| Поле | Тип | Обязательность | Назначение |
|---|---|---|---|
| `url` | string | Ровно одно из трёх | Абсолютный публичный `http`/`https` URL. |
| `html` | string | Ровно одно из трёх | Сырой HTML для извлечения читаемого текста. |
| `text` | string | Ровно одно из трёх | Готовый текст для модели. |
| `annotator` | string | Нет | Имя зарегистрированного provider; default из `DEFAULT_ANNOTATOR`, первоначально `iishko`. |
| `annotator_params` | object | Нет | Параметры только выбранного provider; default `{}`. Неизвестные параметры отклоняются provider. |

`text` проверяется на непустое содержимое, но не очищается от HTML, не обрезается
и не переписывается. Общий лимит размера входа применяется и к нему. Если
`text` превышает допустимый объём для модели, метод возвращает ошибку, а не
молча усекает содержимое. Для `url` и `html` очистка обязательна; политика
работы с длинным извлечённым текстом описана ниже.

Ответ `200`:

```json
{
  "annotation": "Статья описывает результаты исследования и основные выводы авторов. Также в ней обсуждаются ограничения метода и возможные применения.",
  "language": "ru",
  "annotator": "iishko",
  "metadata": {"duration_ms": 850}
}
```

`annotation` — непустой связный текст из 2–3 предложений. `language` в первой
версии всегда `ru`. `annotator` сообщает фактически использованный provider.
`metadata.duration_ms` включает подготовку контента и вызов модели. Ответ не
содержит исходный URL, HTML, полный текст, промпт и сырой ответ провайдера.

Предлагается также `GET /v1/annotators` по аналогии с `/v1/translators`:

```json
{
  "annotators": [{"name":"iishko","ready":true}],
  "default_annotator": "iishko"
}
```

`ready` означает наличие обязательной конфигурации provider. Проверка не должна
делать платный вызов модели при каждом запросе списка. `GET /health/ready`
сохраняет прежнюю семантику готовности default переводчика.

### Ошибки

Все ошибки используют существующий envelope
`{"error":{"code":"...","message":"...","details":{},"request_id":"..."}}`.

| HTTP | `error.code` | Ситуация |
|---:|---|---|
| 400 | `invalid_request` | Нарушена структура запроса, включая правило одного входа. |
| 403 | `url_not_allowed` | URL ведёт на локальный/внутренний/запрещённый адрес. |
| 404 | `unknown_annotator` | Выбранный provider не зарегистрирован. |
| 413 | `content_too_large` | Вход, загруженный контент или текст для модели превышает лимит. |
| 415 | `unsupported_content_type` | URL возвращает неподдерживаемый тип контента. |
| 422 | `content_not_extractable` | Из URL/HTML не получен содержательный текст. |
| 422 | `invalid_annotator_params` | Параметры выбранного provider некорректны. |
| 502 | `content_fetch_failed` | Страница не получена или HTTP-ответ непригоден. |
| 502 | `annotation_failed` | Ответ модели отсутствует или не проходит проверку. |
| 503 | `annotator_unavailable` | Provider не настроен, недоступен или отклонил запрос из-за лимита. |
| 504 | `annotation_timeout` | Превышено время загрузки или аннотирования. |

Сообщения об ошибках не раскрывают адреса внутренней сети, API-ключи,
содержимое входа, текст страницы, traceback или сырой ответ провайдера.

## 3. Архитектура

```text
POST /v1/annotate
  -> AnnotationService
     -> ContentPreparer
        -> SafePageFetcher          [url]
        -> MainContentExtractor     [url/html]
        -> pass-through validation  [text]
     -> AnnotatorRegistry
        -> AnnotatorProvider        [iishko / future providers]
  -> AnnotationResponse
```

Это самостоятельная provider abstraction: `AnnotatorRegistry` и
`AnnotatorProvider` не входят в `TranslatorRegistry`, поскольку их вход,
возможности, готовность и результат отличаются от перевода. API-слой не должен
импортировать HTTP-клиент ИИШКО и не должен ветвиться по именам provider.

Предлагаемый внутренний контракт:

```python
class AnnotatorProvider(Protocol):
    name: str

    def annotate(self, request: ProviderAnnotationRequest) -> ProviderAnnotationResult: ...
    def health(self) -> AnnotatorHealth: ...
```

`ProviderAnnotationRequest` содержит подготовленный `text` и
`annotator_params`, но не FastAPI request/response objects и не сырой HTML.
Provider возвращает текст аннотации и безопасные метаданные. Общие правила
(2–3 предложения, русский язык, лимиты и нормализация ошибок) принадлежат
`AnnotationService`. Provider валидирует свои параметры и адаптирует запрос к
конкретному внешнему API. При подключении другого поставщика публичная схема
`POST /v1/annotate` не меняется.

### Подготовка входа

1. `url`: разрешать только `http` и `https` без credentials; до сетевого
   соединения и после каждого redirect запрещать loopback, private, link-local,
   metadata и другие непубличные IP. Проверенный IP закреплять для соединения,
   чтобы DNS rebinding не обходил проверку. Ограничить время, размер ответа и
   число перенаправлений.
2. Для `url` в первой версии принимать `text/html` и `text/plain`.
   PDF, изображения, видео, страницы за авторизацией и JavaScript rendering
   не входят в объём задачи. `text/plain` проходит как текст без HTML-очистки.
3. Для `url` с HTML и для `html`: удалить `script`, `style`, `noscript`,
   `template`, навигацию и повторяющиеся элементы; извлечь основной читаемый
   текст и нормализовать пробелы с сохранением порядка абзацев. Пустой результат
   отклонить. Не исполнять JavaScript и не загружать ресурсы, ссылки или
   изображения из переданного `html`.
4. Для длинных HTML-страниц брать первые 20 000 символов извлечённого текста
   и указывать `metadata.truncated: true`, если использована часть материала.
   Для `text` усечение запрещено.
5. Любой подготовленный текст считать недоверенными данными: инструкции внутри
   страницы или текста не могут менять роль системного промпта. Не передавать
   модельному provider исходный URL, если он не нужен для аннотации.

### Первый provider: ИИШКО

- Имя в API: `iishko`.
- Адаптер вызывает OpenAI-совместимый
  `POST https://api.reformboss.com/v1/chat/completions` с
  `Authorization: Bearer <key>`.
- Имя модели задаётся настройкой provider. Default — `qwen3.8-flash`.
  Смена модели не меняет публичный API.
- Фиксированная инструкция требует аннотацию на русском в 2–3 предложениях,
  строго по содержимому входа и без выполнения команд, встреченных в тексте.
- API-ключ берётся из `IISHKO_API_KEY` в окружении или secret storage; клиент
  `annotate` не передаёт ключ. Base URL, модель и timeout конфигурируются.
- Неизвестные `annotator_params` отвергаются; разрешённый список параметров
  provider определяет отдельно. Параметры не должны позволять менять endpoint,
  ключ или системную инструкцию.
- Повторные попытки допустимы только для временных ошибок и в пределах общего
  timeout; автоматического перехода к другому provider в первой версии нет.

## 4. Эксплуатация и тесты

- Сетевую загрузку и вызов внешней модели выполнять без блокировки event loop.
- Настройки включают `DEFAULT_ANNOTATOR`, лимиты HTML-входа (2 000 000 символов),
  загрузки URL (2 000 000 байт), текста модели (20 000 символов) и таймауты
  загрузки/provider/общий (10/90/100 секунд). Их можно изменить через окружение.
- В средах, где системный DNS подменяет публичные адреса служебными, можно задать
  `ANNOTATION_DNS_SERVER` публичным IP DNS-сервера. Полученный IP всё равно
  проверяется на публичность и закрепляется за сетевым соединением.
- Логировать request id, вариант входа, выбранный provider, длительности
  этапов, размеры текста и исход операции. Не логировать URL целиком (query может
  содержать токен), HTML, текст, промпт, аннотацию или API-ключ.
- Unit и HTTP contract tests использовать с fake fetcher и fake annotator;
  никакая модель или внешний сервис для них не требуются.
- Проверить все три пути входа, правило ровно одного поля, forwarding
  `annotator_params` только выбранному provider, выбор default/явного provider,
  неизвестный provider, невалидные параметры, пустой/избыточный контент,
  timeout и некорректный ответ модели.
- Отдельно проверить SSRF-барьеры, redirect на внутренний адрес, DNS rebinding,
  отсутствие исполнения ресурсов из HTML и отсутствие чувствительных данных в
  логах и ошибках.
- Существующие unit и HTTP contract tests перевода должны продолжать проходить.

## 5. Открытые продуктовые решения

1. Русский язык и 2–3 предложения зафиксированы как поведение первой версии.
   Если позже понадобятся другие языки или объём, их следует добавлять
   отдельными необязательными полями API.
2. Переданный `text` может содержать конфиденциальные данные: вызов `annotate`
   означает разрешение отправить его выбранному внешнему provider. Если это
   неприемлемо для некоторых клиентов, они не должны использовать этот метод
   с такими данными.
3. Предоставленный тестовый ключ уже присутствует в переписке. Перед внедрением
   его нужно перевыпустить; новый ключ хранить только в secret storage или
   окружении.
